## 3. Правила и решения пользователя (обязательно соблюдать)

- Работа **по одной карточке, по очереди**, не параллельно; каждый результат проверяется глазами. Публикация в `main` — **после каждой 5-й генерации** (и по просьбе пользователя).
- Формат всех слайдов: **Syntx → Nano Banana Pro, 3:4, 2K** (2 токена Syntx за картинку; баланс ~136 на 02.10.2026). Кровать 286 осталась в 16:9 по прямому решению пользователя.
- Диван = слайд из двух панелей (сверху сложенный, снизу разложенный), кровать = один кадр с длиной, шириной (для диапазона — наибольший вариант) и высотой.
- Линии строго параллельны граням в перспективе, вне изделия и его тени; на слайде только цифры в см; идентичность дивана с референсом (цвет отделки, число секций, сторона оттоманки не меняются; зеркальный ракурс симметричного дивана допустим).
- Какое число вдоль какого ребра (диваны): `F` — вдоль **переднего** края спального места, `S` — **вглубь**; считается в `dims_picks.py` как наибольшее значение, не превышающее длину дивана, исключения — словарь `SWAP`/`OVERRIDE`.
- **Интерьер первого слайда** всегда красивый, «продающий», дизайнерский, **каждый раз другой стиль**; диван в ракурсе 3/4 (не анфас), целиком, с отступом ≥10% слева и справа, цвет обивки фиксировать в промпте. Шаблон — `interior-prompt.tpl.txt`.
- Публикация только через **чистый worktree от `origin/main`** (в основной папке много чужих незакоммиченных правок Codex/пользователя), перед пушем `git fetch` и проверка `behind=0`, аудит `node tools/audit-catalog.js` (критичных 0; 4 известных предупреждения: 1 тяжёлое видео и 3 матраса со схемой).
- Учётные данные в Syntx вводит только пользователь; секреты в репозиторий не класть.

## 4. Как продолжить на другой машине (по шагам)

1. `git clone https://github.com/oleg2134234/mebel.hub.git`, `git fetch origin`; прочитать `CLAUDE.md` (правило № 1 — идентичность модели) и этот файл. Нужны Python 3 с Pillow и Node 18+.
2. Данные производителя: `cd tools/apogey60 && node fetch.mjs` → создаст `all.json` (в репозитории его нет, 2,4 МБ). Манифесты `dims-manifest.json`, `dims-picks.json`, `dims-picks-beds.json` уже в репозитории (пересобрать: `python dims_manifest.py`, `python dims_picks.py`, `python dims_beds.py`). Контактные листы превью для выбора кадров: `python dims_sheets.py` и `python dims_sheets.py beds` → `work/dims-sheets*/`.
3. Рабочая папка `work/` — локальная («черновики», в репозиторий не коммитится): скрипты кладут туда `work/dims-<ID>/syntx-<tag>.jpg` и `cmp-<tag>.jpg`.
4. Чистый worktree для публикации: `git worktree add -b dims-pub C:/Temp/claude/pub-dims origin/main` (или любой путь; скрипт принимает путь параметром).
5. **Syntx** (пользователь входит сам, `https://syntx.ai/ru/image/banana`): в настройках модель Nano Banana → *Banana Pro*, формат 3:4, разрешение 2K. В консоли страницы вставить содержимое `dims-lib.js` (оно определяет `window.TPL`, `window.dimsRun(urls, nums)`, `window.dimsResult()`), либо сохранить его в `localStorage.dimsLib` и каждый раз `(0,eval)(localStorage.dimsLib)`. Шаблон кроватей — `dims-bed-prompt.tpl.txt` (присвоить в `window.TPL`).
6. Цикл по одной карточке:
   - новый чат (`location.href='https://syntx.ai/ru/image/banana'`), `await window.dimsRun([url_сложен, url_разложен], [L, D, F, S])` — референсы берутся с `admin.apogey-mebel.ru/uploads/…` (адреса в `dims-picks.json`), числа — из `dims-picks.json`; для кроватей один референс и `[Д, Ш, В, "x"]` из `dims-picks-beds.json`;
   - **страница Syntx сама не обновляется:** подождать ~40 с и сделать `location.reload()`, затем `window.dimsResult()` вернёт ссылку на картинку; если после отправки в поле остался черновик — нажать «отправить» повторно (запрос не ушёл), это видно и по неизменному балансу;
   - `python dims_cmp.py <ID> <url> <tag>` (диваны) или `dims_cmp_bed.py` (кровати) — скачает результат и соберёт сравнение с референсом; проверить глазами;
   - к промпту (`window.TPL += …`) при необходимости добавлять замки: COLOR LOCK, DETAIL LOCK, ORIENTATION LOCK (оттоманка на той же стороне), LABEL ASSIGNMENT IS FIXED (какое число на какой линии), STYLE LOCK (сплошные кружки), ROTATION (нижний диван в том же ракурсе, что верхний), ARMREST CAPS LOCK; для угловых — «диван не зеркалить, не добавлять модули».
7. Принятое сохранить и опубликовать пачкой: `python dims_pub.py <worktree> <ID:tag> …` (кладёт `assets/<slug>/slide_dims.jpg` 1200 px и слайд вторым в `GALLERIES`), затем аудит, коммит с `Co-Authored-By`, `git fetch`, `git push origin HEAD:main`. Точечная правка числа в плашке готового результата: `python dims_fixnum.py <in> <out> <cx,cy исходной плашки> <cx,cy заменяемой>`.
8. Проверка публикации: картинки `https://oleg2134234.github.io/mebel.hub/assets/<slug>/slide_dims.jpg` отдают 200 (Pages выкатывает 1–3 минуты).

## 5. Пилот для угловых диванов (на 02.10.2026, не принят)

Идея: не просить модель перерисовывать диван, а нанести линии на **оригинальное студийное фото**, по одной панели (так сделаны кровати), затем склеить две панели в слайд 3:4. Для панелей в Syntx выставлен формат **4:3** (панель 1200×900, обрезать белые поля до 1200×800 и сложить две в 1200×1600). **После пилота вернуть настройку на 3:4.**

Промпт панели (для сложенного вида; для разложенного — F/S вместо L/D): «Add dimension annotations directly onto this exact sofa photo, WITHOUT changing the sofa or the plain white background in any way … Add exactly two such lines: 1. LENGTH line labelled “363” on the floor along the long front bottom edge of the sofa …, precisely parallel … 2. DEPTH line labelled “188” along the receding side bottom edge of the chaise …, starting at the front corner of the chaise… Every line … outside the sofa and its floor shadow … No other text.» Референс — кадр `urls[0]` из `dims-picks.json` (сложен) или `urls[1]` (разложен).

Первый тест: Бали 7-2 ДКУ-О (279), сложенный вид, 363/188 — результат сгенерирован, **ещё не оценён** (ссылка в чате Syntx: `…/generated/a2e4d8a238b83a1d1524a86464f8b5d3_b25e7bb1-7a9a-4706-82c9-4189528a34c9.jpg`). Если подходит — то же для разложенного вида (303/188), склейка, показ пользователю, публикация. Если нет — вариант «линии рисует Claude по координатам, утверждённым пользователем» (правило из `CLAUDE.md`: положение линий задаёт пользователь).

## 6. Известные особенности и ловушки

- Syntx: первая отправка сразу после загрузки референсов иногда не уходит (чат создаётся, поле не очищается) — повторить; результаты появляются только после перезагрузки страницы.
- Скачивать картинки с `r2.syntx.ai` нужно с заголовком `User-Agent` (без него 403).
- Страница каталога тяжёлая (см. выше), в браузерной панели карточка может загружаться десятки секунд; для просмотра слайда открывать файл картинки напрямую.
- Файл `index.html` хранит `IMAGES`/`GALLERIES` одной строкой JSON — вставлять слайд точечной строковой вставкой (`dims_pub.py`), не пересериализовать.
- Токены Syntx: перегенерации тратят баланс (2 за картинку); большинство повторов были из-за зеркального ракурса, перепутанных подписей, выдуманных деталей отделки и «упрощения» модели.
