# Чат-бот продажник для sytnie-ugodya.ru

AI-консультант на Claude API для сайта «Сытные угодья»: отвечает на вопросы о продукции,
выявляет потребность клиента (розница/опт), отрабатывает типовые возражения, собирает
контакт и передаёт заявку менеджеру. Работает на сайте (виджет) и, опционально, напрямую
в Telegram — с одинаковой логикой и знаниями в обоих каналах. Плюс простая CRM-панель со
списком заявок и ручной рассылкой по email.

**Чтобы установить бота на сайт — см. пошаговую инструкцию в [`DEPLOY.md`](./DEPLOY.md)**
(деплой бэкенда, вставка виджета под разные CMS, чек-лист запуска).

Состоит из двух частей:

- **`widget/widget.js`** — встраиваемый чат-виджет (чистый JS, без зависимостей). Вставляется
  одним тегом `<script>` на любой сайт.
- **`server/`** — бэкенд на Node.js/Express: хранит API-ключ Claude, обрабатывает диалог,
  сохраняет заявки и уведомляет менеджера (Telegram/email). Ключ Claude **никогда** не должен
  попадать в браузер — поэтому нужен именно бэкенд-прокси, а не прямой вызов API из виджета.

## Как это работает

Два варианта установки на сайт — можно использовать любой или оба сразу:

**A. Кнопка-ссылка на Telegram-бота (основной сценарий).** Клиент видит на сайте кнопку
«Спросить в Telegram», переходит в бота и там же ведёт весь диалог — вопросы, возражения,
заявка. Никакого JS-виджета с чат-окном на сайте не требуется, только сама кнопка.

**B. Встроенный чат-виджет.** Диалог идёт прямо на сайте, в плавающем окне, без перехода
в Telegram.

В обоих случаях диалог обрабатывает один и тот же бэкенд и один и тот же системный промпт
(`server/knowledge.js`), поэтому бот отвечает одинаково независимо от канала:

1. Клиент пишет сообщение — в Telegram-боте или в виджете на сайте.
2. Бэкенд обращается к Claude API с системным промптом о компании «Сытные угодья» и
   инструментом `submit_lead`.
3. Когда бот выяснил потребность клиента и получил его имя + контакт, он вызывает
   `submit_lead` — бэкенд сохраняет заявку локально и уведомляет менеджера в Telegram и/или
   на email.
4. Менеджер открывает `/admin` (защищено логином/паролем), видит список заявок, меняет их
   статус (новая/в работе/закрыта) и может вручную разослать письмо по выбранным заявкам,
   у которых контакт указан как email.

## Быстрый старт (локально)

```bash
cd chatbot/server
npm install
cp .env.example .env
# впишите в .env как минимум ANTHROPIC_API_KEY
npm start
```

Бэкенд поднимется на `http://localhost:3001`. Откройте `chatbot/widget/demo.html`
(см. ниже) или добавьте тег виджета на любую тестовую HTML-страницу с `data-api-url`,
указывающим на `http://localhost:3001/api/chat`.

## Переменные окружения (`server/.env`)

| Переменная | Обязательна | Назначение |
|---|---|---|
| `ANTHROPIC_API_KEY` | да | Ключ Claude API (console.anthropic.com) |
| `CLAUDE_MODEL` | нет | По умолчанию `claude-opus-5`. Для большого потока сообщений дешевле `claude-sonnet-5` — качество для такого сценария вполне достаточное. |
| `PORT` | нет | Порт бэкенда, по умолчанию 3001 |
| `ALLOWED_ORIGINS` | рекомендуется | Список доменов через запятую, которым разрешено дёргать API (домен вашего сайта) |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | нет | Уведомления о новых заявках в Telegram |
| `TELEGRAM_CUSTOMER_BOT` | нет | `true` — включить бота как канал общения с клиентами (сценарий A, кнопка → Telegram) |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`, `LEADS_EMAIL_TO` | нет | Уведомления о заявках на почту + рассылка из админки |
| `ADMIN_USER`, `ADMIN_PASS` | нет | Логин/пароль для `/admin`. Пока не заданы — панель отвечает 503 |

Настройте хотя бы один канал уведомлений (Telegram или email) — иначе о новых заявках
можно будет узнать только из `server/data/leads.json` через `/admin`.

## Деплой бэкенда и встраивание на сайт

Полная пошаговая инструкция (Docker/Render/VPS, вставка тега под Тильду, WordPress,
Bitrix и обычный HTML, чек-лист запуска) — в [`DEPLOY.md`](./DEPLOY.md).

Коротко: бэкенд — обычное Node.js/Express-приложение, отдаёт само себя, файл виджета
(`GET /widget.js`) и файл Telegram-кнопки (`GET /telegram-button.js`) — отдельно хостить
их не нужно.

**Сценарий A — кнопка → Telegram (основной).** Заведите бота через @BotFather, включите
`TELEGRAM_CUSTOMER_BOT=true` в `.env`, задеплойте бэкенд — и вставьте на сайт перед
`</body>`:

```html
<script
  src="https://your-backend.example.com/telegram-button.js"
  data-bot="your_bot_username"
  data-accent="#8a4a2a"
  async
></script>
```

`data-bot` — юзернейм бота без `@` и без `t.me/`.

**Сценарий B — встроенный чат-виджет.** Вставьте на сайт перед `</body>`:

```html
<script
  src="https://your-backend.example.com/widget.js"
  data-api-url="https://your-backend.example.com/api/chat"
  data-accent="#8a4a2a"
  async
></script>
```

Параметры `data-*` на теге `<script>` виджета:

| Атрибут | По умолчанию | Назначение |
|---|---|---|
| `data-api-url` | `/api/chat` | URL бэкенда (обязательно укажите свой) |
| `data-accent` | `#8a4a2a` | Акцентный цвет виджета |
| `data-title` | `Сытные угодья` | Заголовок в шапке чата |
| `data-subtitle` | `Онлайн-консультант` | Подзаголовок |
| `data-greeting` | (см. `widget.js`) | Первое сообщение бота |

## Админ-панель заявок

`https://your-backend.example.com/admin` (логин/пароль из `ADMIN_USER`/`ADMIN_PASS`):

- список заявок с фильтрами по статусу и типу клиента (розница/опт);
- смена статуса заявки (новая → в работе → закрыта);
- ручная рассылка по email выбранным заявкам (для заявок с контактом-телефоном рассылка
  недоступна — свяжитесь с клиентом вручную; чтобы разослать и по телефону/WhatsApp,
  понадобится подключить отдельного провайдера SMS/WhatsApp Business API — это не входит
  в текущую реализацию).

## Обучение бота продажника

Всё «обучение» бота — это системный промпт в `server/knowledge.js` (`SYSTEM_PROMPT`).
Там уже прописаны:

- факты о компании и ассортименте (`# О компании`, `# Ассортимент`, `# Преимущества`,
  `# Условия хранения и срок годности`, `# Розница и опт`);
- сценарий продажи по шагам: выявление типа клиента → потребность → подбор ассортимента →
  релевантные преимущества → мягкий кросс-селл → сбор контакта (`# Сценарий диалога`);
- отработка типовых возражений — «дорого», «почему консервы», «что в составе», «есть ли
  халяль», «условия для опта», «сроки доставки» (`# Работа с возражениями`).

Чтобы «доучить» бота — редактируйте `SYSTEM_PROMPT` в этом файле: добавляйте новые факты,
уточняйте формулировки, добавляйте новые возражения по мере того, как они реально
встречаются в диалогах. Не добавляйте туда цифры (цены, сроки, минимальные партии),
которых у вас нет в исходных данных, — бот специально не должен их выдумывать.

## Каналы общения с клиентом

| Канал | Статус | Как включить |
|---|---|---|
| Telegram (бот отвечает клиентам напрямую) | Готово | `TELEGRAM_CUSTOMER_BOT=true` + кнопка `telegram-button.js` на сайте |
| Встроенный чат-виджет на сайте | Готово | `widget.js` на сайте |
| MAX (мессенджер VK) | Не реализовано | Нужна документация Bot API MAX — добавить не получилось: сеть окружения, в котором собирался проект, блокирует `dev.max.ru`, а угадывать формат запросов вслепую рискованно. Пришлите доки/токен — добавлю по аналогии с Telegram-модулем (`server/telegramBot.js`) |

## Ограничения текущей версии

- Хранилище заявок — простой JSON-файл (`server/data/leads.json`), без поддержки
  одновременной записи из нескольких процессов. Для небольшого потока заявок этого
  достаточно; при росте нагрузки стоит перейти на настоящую БД.
- История диалога в Telegram-боте хранится в памяти процесса (сбрасывается при
  перезапуске сервера) — этого достаточно для теста, для продакшена стоит вынести в БД.
- Рассылка работает только по email; для телефона/WhatsApp нужен отдельный провайдер.
- Бот не называет точные розничные и оптовые цены — этому специально обучен системный
  промпт, чтобы не выдумывать цифры; расчёт всегда передаётся менеджеру.
