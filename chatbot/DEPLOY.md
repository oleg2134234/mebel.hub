# Установка на sytnie-ugodya.ru — пошагово

Два шага: **1) поднять бэкенд** (он держит ключ Claude API и ведёт диалог),
**2) вставить на сайт одну ссылку/кнопку**. Ниже — оба шага подробно.

## Самый быстрый способ получить рабочий тест (Telegram + Render, без сервера)

Если нужно быстро проверить бота живьём — это самый короткий путь, без своего сервера и
без Docker:

1. В Telegram напишите **@BotFather** → `/newbot` → получите токен бота и его юзернейм.
2. Разверните бэкенд на Render.com — см. «Вариант B» ниже (5 минут, без сервера).
3. В переменных окружения Render добавьте `TELEGRAM_BOT_TOKEN` (из шага 1) и
   `TELEGRAM_CUSTOMER_BOT=true`.
4. Откройте бота в Telegram по его юзернейму, нажмите `/start` — бот сразу отвечает и
   ведёт диалог по сценарию продаж из `server/knowledge.js`.
5. На сайте добавьте кнопку-ссылку на бота (шаг 2, сценарий A ниже) — весь остальной чек-лист
   можно пройти уже после того, как убедитесь, что бот отвечает адекватно.

## Шаг 1. Поднять бэкенд

Нужен любой хостинг с Node.js 18+ или с поддержкой Docker. Ниже — три рабочих варианта,
выберите один.

### Вариант A. Docker на своём VPS (рекомендую, если сервер уже есть)

```bash
cd chatbot/server
cp .env.example .env
# впишите в .env как минимум ANTHROPIC_API_KEY, а также ALLOWED_ORIGINS=https://sytnie-ugodya.ru
docker compose up -d --build
```

Бэкенд поднимется на порту 3001 контейнера. Дальше нужен обратный прокси с HTTPS
(Nginx/Caddy) до этого порта — виджет обязан ходить на `https://`, иначе браузер
заблокирует запрос со страницы сайта (mixed content). Пример конфига Caddy:

```
bot.sytnie-ugodya.ru {
    reverse_proxy localhost:3001
}
```

Caddy сам получит SSL-сертификат. Для Nginx понадобится Certbot отдельно.

### Вариант B. Render.com (без своего сервера, проще всего для старта)

1. Загрузите репозиторий на GitHub (или используйте текущий).
2. На render.com → **New → Web Service** → укажите репозиторий, Root Directory:
   `chatbot/server`.
3. Build Command: `npm install`, Start Command: `node server.js`.
4. В Environment Variables впишите переменные из `chatbot/server/.env.example`
   (как минимум `ANTHROPIC_API_KEY`, и `ALLOWED_ORIGINS=https://sytnie-ugodya.ru`).
5. **Важно**: у Render бесплатный диск эфемерный — файл заявок `data/leads.json` будет
   стираться при передеплое. Если это критично, подключите постоянный диск (Render Disks,
   платно) с точкой монтирования `/opt/render/project/src/chatbot/server/data`, либо
   переходите на вариант A/C с volume.
6. После деплоя Render даст вам URL вида `https://ваш-сервис.onrender.com`.

### Вариант C. Обычный VPS без Docker

```bash
cd chatbot/server
npm install --omit=dev
cp .env.example .env   # заполните переменные
npm start               # или через pm2/systemd, чтобы процесс не падал при рестарте сервера
```

Тоже потребуется обратный прокси с HTTPS (см. вариант A).

### Обязательные переменные окружения

Заполните `chatbot/server/.env` (см. полный список и комментарии в `.env.example`):

- `ANTHROPIC_API_KEY` — ваш ключ Claude API.
- `ALLOWED_ORIGINS=https://sytnie-ugodya.ru,https://www.sytnie-ugodya.ru` — иначе браузер
  заблокирует запросы виджета с сайта (CORS).
- Хотя бы один канал уведомлений о заявках: `TELEGRAM_BOT_TOKEN`+`TELEGRAM_CHAT_ID`
  и/или `SMTP_*`+`LEADS_EMAIL_TO`.
- `ADMIN_USER`+`ADMIN_PASS` — чтобы открыть `/admin` и видеть заявки.

## Шаг 2. Установить на сайт

Отдельно хостить файлы виджета/кнопки не нужно — бэкенд сам их отдаёт (`GET /widget.js`,
`GET /telegram-button.js`). Выберите сценарий.

### Сценарий A — кнопка ведёт в Telegram-бота (основной)

Клиент кликает по кнопке на сайте, попадает в Telegram и там же ведёт весь диалог с
ботом — до заявки. Требует включённого `TELEGRAM_CUSTOMER_BOT=true` на бэкенде
(см. «Самый быстрый способ» выше).

```html
<script
  src="https://ваш-бэкенд.example.com/telegram-button.js"
  data-bot="юзернейм_вашего_бота"
  data-accent="#8a4a2a"
  async
></script>
```

`data-bot` — юзернейм бота из @BotFather, без `@` и без `t.me/`.

### Сценарий B — встроенный чат прямо на сайте

Диалог идёт в плавающем окне на странице сайта, без перехода в Telegram.

```html
<script
  src="https://ваш-бэкенд.example.com/widget.js"
  data-api-url="https://ваш-бэкенд.example.com/api/chat"
  data-accent="#8a4a2a"
  async
></script>
```

Оба варианта — обычные теги `<script>`. Вставить нужно **перед `</body>`**. Как именно —
зависит от того, на чём сделан сайт:

### Тильда (Tilda)

Сайт → Настройки сайта → **Ещё** → **Вставка кода (T123)** → поле «Код для вставки в
конце HTML-кода (перед `</body>`)» → вставьте тег скрипта → Сохранить.

### WordPress

Проще всего — через плагин типа **Insert Headers and Footers** (или аналогичный):
Настройки → Insert Headers and Footers → поле «Footer» → вставьте тег → Сохранить.
Если плагинов не хочет ставить — можно вставить тег в `footer.php` темы перед `</body>`
(Внешний вид → Редактор тем), но это слетит при обновлении темы.

### Bitrix / 1С-Битрикс

Через административную панель: Настройки → Настройки продукта → **Веб-аналитика**
(или похожий раздел «Коды для вставки на все страницы» в зависимости от редакции) →
добавьте тег в область перед `</body>`. Если такого раздела нет — попросите
разработчика сайта вставить тег в шаблон `footer.php` компонента.

### Обычный HTML-сайт (руками/через FTP)

Откройте файл(ы) с версткой каждой страницы (или общий футер-инклюд, если он есть) и
вставьте тег скрипта прямо перед закрывающим тегом `</body>`.

## Проверка после установки

1. **Telegram-бот (сценарий A)**: откройте бота по юзернейму, `/start` — должен прийти
   приветственный текст. Напишите тестовое сообщение как розничный клиент, затем как
   оптовик — проверьте, что бот верно определяет тип клиента и не выдумывает цены.
2. **Виджет (сценарий B)**: откройте сайт в браузере — в правом нижнем углу должна
   появиться круглая кнопка чата; консоль браузера (F12 → Console) — без ошибок CORS/сети.
3. Доведите тестовый диалог (в любом канале) до передачи контакта — проверьте, что
   уведомление пришло в Telegram/на почту (в зависимости от того, что настроили).
4. Откройте `https://ваш-бэкенд.example.com/admin`, авторизуйтесь — тестовая заявка
   должна быть видна в списке.

## Чек-лист запуска

- [ ] Бэкенд задеплоен и `https://ваш-бэкенд/api/health` отвечает `{"ok":true}`
- [ ] `ANTHROPIC_API_KEY` вписан, тестовый диалог отвечает осмысленно
- [ ] Настроен хотя бы один канал уведомлений менеджеру (Telegram и/или email)
- [ ] `ADMIN_USER`/`ADMIN_PASS` заданы, `/admin` открывается и показывает заявки
- [ ] Сценарий A: `TELEGRAM_CUSTOMER_BOT=true`, `TELEGRAM_BOT_TOKEN` задан, бот отвечает
      на `/start` и на вопросы; кнопка `telegram-button.js` с верным `data-bot` вставлена
      на сайт
- [ ] Сценарий B: `ALLOWED_ORIGINS` включает домен сайта; `widget.js` доступен по HTTPS
      и вставлен на сайт перед `</body>`; кнопка чата видна, диалог работает
- [ ] Заявка доходит до менеджера (уведомление) и видна в `/admin`
- [ ] Проверены сценарии: розница, опт, типовые возражения (см. `server/knowledge.js`)
