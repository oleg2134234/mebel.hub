# Карточки Apogey через Syntx

Состояние работ и остаток — в `tools/apogey60/HANDOFF.md` и в разделе «Добавление 60 отсутствующих карточек Apogey» файла `docs/catalog/PLAN.md`. Сначала прочитай их и `CLAUDE.md` (правило № 1 — идентичность модели).

## Правила (решения пользователя)
- Один слайд на карточку: «В интерьере», 3:4, Syntx Nano Banana Pro, 2K, 2 токена за картинку. Не больше одной генерации на карточку; повтор — только если модель не совпала с оригиналом (число секций, сторона оттоманки, цвет, пропорции).
- Интерьер каждый раз другой — дизайнерский, студийный, «продающий»; пропорции строго как на референсе; без людей, текста и логотипов.
- Матрасы: официальная схема/листовка производителя вместо генерации.
- Подпись под слайдом: 2 преимущества из `advantages` API + короткий продающий текст + слово «Визуализация.» (короче, чем в первых версиях — иначе не влезает в экран).
- Публикация в `main` — пачками по 5 генераций, только по разрешению пользователя; перед публикацией на другой машине сверить `git fetch` и `git status`.

## Конвейер (скрипты — `tools/apogey60/`)
Пути в скриптах рассчитаны на `C:/Temp/claude/work` (рабочие файлы) и `C:/Temp/claude/pub` (git worktree от origin/main, ветка `apogey-pub`) — при переносе на другую машину поправить константы `WORK`/`PUB` в `addcard.mjs`, `pub.sh`, `push.sh`, `getgen.sh`, `recaption.mjs`, `redesc.mjs`, `series.py`.

1. `node fetch.mjs` — выгрузка API apogey-mebel.ru (публичный токен берётся из JS сайта на лету) → `all.json`.
2. `rows.txt` (номер|категория|название|ID на сайте|dims|) → `python mkcards.py` → `cards.json`. Габариты: длина ≥ ширина; у кроватей `dims` = `длина×ширина_корпуса_мин-макс×высота`; в `desc` обязательно «Спальное место N/N×2000 мм» — иначе квиз по ширине не найдёт кровать.
3. Syntx (залогиненный браузер): вставить `setup.js` в консоль страницы `syntx.ai/ru/image/banana`, затем `window.run(<localId>)` — создаёт новый чат, подгружает 2 референса с admin.apogey-mebel.ru, вставляет промпт, отправляет; результат в `window.res.url` (без `_500` — полное разрешение 1792×2400). Ожидание — циклом по 3 с, не дольше 40 с на вызов инструмента.
4. `getgen.sh <localId> <webId> <url>` → `gen/<id>.jpg` + `gen/<id>_cmp.jpg` (оригинал слева, результат справа). Сравнить глазами: форма, число секций/подушек, сторона оттоманки (при зеркале — отразить файл по горизонтали), цвет.
5. `pub.sh <localId>` — запись в `PRODUCTS/IMAGES/GALLERIES` + коммит; `push.sh` — публикация.
6. `python series.py` — новые модели в существующие серии `PRODUCT_SERIES` (берёт только существующие ID), новые серии по линейкам.
7. Проверка: консоль без ошибок, нет дублей ID, у всех есть IMAGES/GALLERIES, квиз (`matchesFormat`, `bedSleepWidthsMm`, `rangeAt`), поиск и категории; затем публичные URL картинок после деплоя Pages.

## Подводные камни
- Если на сайте у студийного фото другой цвет, чем у интерьерного, в промпте цвет и длина — строго по Image 1 (первое фото).
- Вызов инструмента браузера обрывается через ~45 с: запускай `run()` без `await`, затем опрашивай `window.res`.
- Кнопка «+» (новый чат) смещается после закрытия верхнего баннера — `run()` ищет её по положению в тулбаре.
- Не хранить токены, ключи и cookies в репозитории.
