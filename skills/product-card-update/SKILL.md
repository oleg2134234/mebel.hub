# Доработка карточки товара (mebel.hub)

Полный маршрут для правки одной карточки по ссылке на сайт-реселлер (обычно `https://emanzhelinsk.mebvektor.ru/products/divan-<slug>` или похожий поддомен mebvektor.ru — если конкретная ссылка не дана, попробуй этот паттерн, слаг обычно транслитерация названия модели).

Сначала прочитай раздел «Порядок создания новой карточки товара» в `CLAUDE.md` и соблюдай его полностью. Он задаёт общий процесс для ссылок, папок с фотографиями и исходных видео. Следующие шаги дополняют этот процесс для карточек, у которых есть страница поставщика.

## Шаг 1 — сверить данные с сайтом

1. Открой ссылку через браузер (`get_page_text`) — вытащи «Спальное место», «Высота изделия», «Ширина изделия», «Длина изделия», «Механизм трансформации».
2. Сравни с текущими `dims`/`desc` в `PRODUCTS` (см. ниже, как найти) — **не переписывай молча**: если совпадает, так и скажи одной строкой; если расходится (особенно спальное место или один из габаритов), покажи расхождение и спроси/использую сайт как источник истины, но явно предупреди.
3. Реальные фото товара: через `javascript_tool` вытащи все `/files/products/...800x600...` URL со страницы (regex по `fetch(location.href)`), **сохраняя querystring-токен** — без него скачивание вернёт «bad token» вместо файла. Скачай нужные (`curl -sL "<url>" -o file.jpg`) во временную папку, посмотри через Read, выбери подходящие для карточки (общий вид, сбоку, разложенный, конструкция и т.д.).

## Шаг 2 — привести слайды к шаблону

Целевой порядок первых трёх слайдов: **1) интерьер, 2) «Уют» (человек + питомец), 3) «Размеры»** — дальше уже что угодно (реальные фото, схема раскладки, видео). Если порядок другой — просто переставь в JSON, это бесплатно (см. Шаг 3).

**Слайд «Размеры»** — ОДИН слайд (не два раздельных «сложенный/разложенный»), светло-серый студийный фон, без интерьера, без заголовков, без иконок-плашек, без единиц измерения («см») — только диван и размерные линии с цифрами. Ровно одна плашка на каждый размер (частый баг генерации — модель рисует одну и ту же цифру дважды, всегда проверяй результат глазами и, если дубль есть, отправляй короткий фикс-промпт «убери дублирующую плашку»).

- Если есть реальные фото сложенного И разложенного вида — комбинируй их напрямую в один слайд.
- Если реального разложенного фото нет, а у модели есть «сосед» по серии с тем же механизмом раскладки (тот же тип: «Дельфин», «Тик-так», модульная секция и т.п.) — можно переиспользовать реальное разложенное фото соседа как референс **формы**, явно попросив перекрасить в цвет текущей модели, а не соседа.
- Не добавляй «слайд конструкции»/«разрез» и «слайд уюта» одновременно без надобности — это отдельные позиции, делай только то, что просили.

**Слайд «Уют»** — фотореалистичная лайфстайл-сцена: человек отдыхает на мебели, рядом питомец (кот/собака), тёплый вечерний свет, без текста/логотипов. Промпт-шаблон:
> Создай фотореалистичную лайфстайл-сцену: этот диван/кресло/кровать (форма, цвет обивки — {цвет}, и материалы точно как на референсном фото) в уютном домашнем интерьере. На диване отдыхает человек, рядом — домашнее животное (кот или собака). Тёплое вечернее освещение, атмосфера уюта. Без текста, без заголовков, без иконок-плашек — просто чистая фотореалистичная сцена.

Всегда используй реальное фото товара (`slides[0].src` или похожее) как `--image`-референс, чтобы диван не «поплыл» по форме/цвету.

Генерация — через `C:\Users\user\Claude\kie-nanobanana\nano_banana.py` (модель `nano-banana-pro`). **Перед запуском платной генерации всегда показывай промпт по-русски в чате и жди подтверждения** (см. память `feedback_kie_generation_approval`) — это касается каждого нового изображения, кроме случаев, когда Олег уже одобрил пачку из нескольких генераций одним «да».

## Шаг 3 — обновить данные карточки

`index.html` хранит `PRODUCTS` и `GALLERIES` как два гигантских однострочных JS-литерала. Номера строк плывут по мере роста файла — сначала:
```
grep -n "^  const PRODUCTS\|^  const GALLERIES" index.html
```
Правь через инлайн Python-скрипт: прочитать строку → `json.loads()` объект между `= ` и `;` → изменить → `json.dumps(..., ensure_ascii=False)` обратно → вставить в строку → записать файл. **Не печатай кириллицу в Bash-консоль напрямую** (крашится на cp1251) — пиши дампы в scratch `.txt` через `io.open(..., encoding='utf-8')` и читай через Read tool, потом удаляй временный файл.

## Шаг 4 — проверить и запушить

1. Локальный превью: `.claude/launch.json` уже настроен (`preview_start` с `name: "mebel-hub"`, реальный Python по абсолютному пути, не системный `python`/`python3` — они нерабочие заглушки Windows Store).
2. Проверь консоль на ошибки (`read_console_messages`, `onlyErrors: true`).
3. Коммить и пушить **только когда Олег явно просит** («пуши», «запуши») — не делай это по умолчанию после каждой правки, но и не жди отдельного разрешения на генерацию/правку самого файла, только на публикацию наружу.
